# Spec: multi-pos-extraction（增量）

## ADDED Requirements

### REQ-MP-005: 词性与释义内联格式（模型 C）

`chinese` 字段必须以 **"词性 + 释义"** 内联格式存储，多词性条目之间使用 ` | ` 分隔。

**WHY**: 让用户清楚看到每个释义对应哪个词性。

**示例**:
```
单词性: chinese="adj. 复杂的"
多词性: chinese="n. 学徒，徒弟; 新手 | vt. 使…做学徒"
```

**约束**:
- 单词性条目也带前缀（统一格式，便于前端处理）
- 同一词性下多个释义用 `; ` 拼接（与原 PDF 格式一致）
- `pos` 字段保留为 `"n.; vt."` 形式（兼容现有查询）

### REQ-MP-006: 续行类型 A — 音标残尾带词性释义

解析器必须识别这种续行：行首是音标残尾（含 `]`），后接词性 + 释义。

**示例**:
```
PDF 行: "əˈdɪkt (for v.)] vt. 使沉溺；使上瘾"
应识别: pos="vt.", chi="使沉溺；使上瘾"
合并到主条目 (addict)。
```

**WHY**: addict、survey 等条目第二个词性的释义在这种续行中。

### REQ-MP-007: 续行类型 B — 纯词性释义续行

解析器必须识别行首直接是词性标记（如 `vi.`、`adj.`）的续行。

**示例**:
```
PDF 行: "vi. 测量土地"
应识别: pos="vi.", chi="测量土地"
合并到主条目 (survey)。
```

### REQ-MP-008: 续行扫描终止条件

向下扫描续行时遇到以下任一情况立即停止：
- 行首是 `\d+\.` 模式（下一个词条开始）
- 行不匹配任何已知续行模式（类型 A/B/C/D）

### REQ-MP-009: `(for xxx.)` 词性提取

PDF 中音标内嵌的 `(for adj.` / `(for v.` 等注释，其中的词性标记必须提取为有效词性。

**示例**:
```
PDF: "appropriate 英 [əˈprəʊprɪət;(for adj. 占用，拨出"
提取: phonetic="əˈprəʊprɪət;", pos="adj.", chi="占用，拨出"
```

**WHY**: 当前行为是把整个 `(for adj.` 当注释丢弃，导致 appropriate 没有词性。

### REQ-MP-010: 字符间空格修复

在续行内容中，必须处理 PDF 排版引擎在字符间插入的空格。

**示例**:
```
PDF 提取: "v t . 使 沉 溺；使 上 瘾"
修复后: "vt. 使沉溺；使上瘾"
```

**约束**:
- 仅在续行处理中应用（避免误伤主行的英文单词间空格）
- 仅压缩"单 ASCII 字母 / 单中文字 + 单空格"模式
- 必须保留有意义的空格（如词性标记 `n. xxx` 中点后的空格）

### REQ-MP-011: 空释义忽略

若某词性提取后释义为空字符串，则该词性条目不进入最终输出。

**示例**:
```
解析中间状态: meanings = [('n.', '拍卖'), ('vt.', '')]
最终输出: chinese="n. 拍卖"  (vt. 因为没释义被忽略)
pos="n."
```

**WHY**: 避免 `auction` 类条目出现 `"拍卖;; 拍卖;竞卖"` 双分号问题。

## MODIFIED Requirements

### REQ-MP-001: 多词性提取（修订）

**之前**：输出 `pos="n.; vt."`、`chinese="学徒;新手;使…做学徒"`（扁平拼接）

**现在**：内部使用 `list[(pos, chinese)]` 结构，最终序列化为模型 C 格式。
- `chinese` 输出格式：`"n. 学徒，徒弟; 新手 | vt. 使…做学徒"`
- `pos` 输出格式：`"n.; vt."`（保持兼容）
